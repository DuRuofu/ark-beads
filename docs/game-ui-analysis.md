# 游戏拼豆界面分析

本文档基于 `research/game-ui/` 中的界面截图、操作视频和网站导出 JSON。

## 已确认的界面结构

- 中央画布是 24×24 方格。
- 第 12 行/列之后有较粗的中线，将画布视觉上分成四个 12×12 区域。
- 左侧导航器实时显示作品缩略图，但不参与自动绘制。
- 右侧编辑区包含预览开关、撤销、重做和颜料列表。
- 颜料列表固定为 4 列、共 10 行，即 40 色。
- 顶部状态下一屏可完整操作约 6 行颜色。
- 颜料列表通过直接上下拖动滚动，不是分页切换。
- 颜色选中后，色块外围出现青色高亮边框。
- 画布支持单格着色；视频还展示了撤销、重做、保存草稿和重新进入编辑器。

## 截图中的参考坐标

原始截图尺寸为 2662×1696。以下坐标仅用于验证测量方法，正式程序不应硬编码：

- 画布外框约为 `(611, 397)` 到 `(1782, 1569)`。
- 画布宽高约为 1171 像素。
- 单格间距约为 48.8 像素。
- 左上格中心约为 `(636, 422)`。
- 右下格中心约为 `(1758, 1545)`。
- 顶部状态调色板第一格中心约为 `(2058, 745)`。
- 调色板列间距约为 145 像素，行间距约为 144 像素。

正式实现将使用用户校准点计算坐标，从而适配窗口尺寸和 Retina/HiDPI 缩放。

## JSON 格式

实际文件结构为：

```json
{
  "size": 24,
  "cells": [
    {
      "x": 0,
      "y": 0,
      "seq": 1,
      "region": 1,
      "hex": "#FFFFFF",
      "palPos": "第1行第4列"
    }
  ]
}
```

已验证：

- `size` 为 24。
- `cells` 恰好包含 576 项。
- `x`、`y` 的范围均为 0–23。
- 数据按从左到右、从上到下的行优先顺序排列。
- `seq = y × 24 + x + 1`。
- `region` 分别对应左上、右上、左下、右下四个 12×12 象限。
- `hex` 是六位十六进制 RGB 颜色。
- `palPos` 直接给出 10×4 调色板中的行列位置。
- 当前模板使用了 20 种颜色，但文件格式可以引用全部 40 个调色板位置。
- 当前文件没有空值或透明值，每个格子都有一种颜色；其中白色占 251 格。

MVP 应优先使用 `palPos` 进行颜色分组。这样不需要通过截图识别颜色，也不需要在首版维护完整的官方 40 色表。

## 推荐绘制策略

1. 导入并严格校验 JSON。
2. 按 `palPos` 将 576 个格子分组。
3. 将调色板重置到顶部。
4. 绘制调色板第 1–5 行涉及的颜色。
5. 将调色板拖动到底部。
6. 绘制调色板第 6–10 行涉及的颜色。
7. 同一颜色内部按画布行优先、相邻行反向的蛇形顺序点击。
8. 绘制结束后停下，由用户检查并手动保存或发布。

选择第 1–5 行和第 6–10 行作为两个稳定区间，可以避开滚动边界处只露出一部分的色块，同时整张图最多只需要一次调色板状态切换。

## MVP 校准数据

首版只需要保存以下数据：

- 左上格中心。
- 右下格中心。
- 顶部状态下调色板第一格中心。
- 调色板横向和纵向间距。
- 将调色板拖到底部的起点、终点和拖动时长。
- 底部状态下用于第 6–10 行的第一个参考色块中心。
- 当前窗口或显示器标识及缩放信息。

## 运行安全要求

- 开始前倒计时。
- 单格测试模式。
- 全流程模拟预览，不移动鼠标。
- 暂停和紧急停止。
- 可配置点击间隔。
- 执行时检测游戏窗口是否仍在原位置。
- 不自动点击保存或完成并发布。
- 首次实机测试限制为少量格子，确认坐标后再解除限制。

## 已补充确认

- 空白画布等同白色，白色格子无需点击。
- macOS 和 Windows 均使用官方客户端，游戏窗口比例固定且不能自由缩放。
- 画布支持按住鼠标连续划过多个格子填色。
- 网站导出时，不透明像素包含 `hex` 和 `palPos`；透明像素的两个字段均为 `null`。
- 已从网站公开前端脚本核对完整的官方 40 色表和导出算法。
